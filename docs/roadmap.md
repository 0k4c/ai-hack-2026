# ロードマップ：AIシフト管理サービスと提出までの計画

2026-09-21更新。日付は日本時間。[Issue #11](https://github.com/0k4c/ai-hack-2026/issues/11) とユーザーの明示依頼に基づき、主目的を関連文書へ反映しました。

**主目的は、ユーザーフレンドリーなAIシフト管理サービスです。** 勤務希望の取り込みからシフト案作成・修正・確定までを中心にし、欠勤対応をその後につなぎます。[企画概要](proposal.md) と [要件定義](requirements.md) の概要レビュー後、詳細仕様・提出範囲・担当・日程を具体化します。以下の新しい実装順序は提案であり、中心機能が提出までにすべて完成するという約束ではありません。

公式提出期限は既存の [公式条件のまとめ](event-brief.md) に記載された **9/22（火）15:00**、9/23は発表日です。期限への対応とサービスの主目的は区別し、未実装部分を明記して提出範囲を人が判断します。

## 次の実装順序案

| 順序 | 作業 | 依存・完了の見え方 |
| --- | --- | --- |
| 1 | 概要を確認し、S1〜S3の詳細を実装Issueへ分解 | 期間・勤務枠・条件・提出範囲を決める。各Issueに入力例、期待結果、完了条件、担当ファイルを書く |
| 2 | 共通データの形と S1 の条件設定・希望取り込み | 従業員・希望・必要人数・対象期間を画面から設定し、解釈の確認・修正ができる。処理と画面の入出力を先に合意する |
| 3 | S2 の案作成と検証 | S1のデータからシフト表を作る。不足・重複・勤務条件の問題が具体的に分かる |
| 4 | S3 の表の表示・編集・確定・保存 | 修正後も再検証し、人の確定操作で保存・再表示できる。生成処理と並行する画面作業は合意した入出力の範囲で行う |
| 5 | 欠勤対応との接続と通し確認 | 確定した表から欠勤対応へ進め、承認結果の扱いが整合する。#34の解決を確認する |
| 6 | 実装済みの範囲でデモ・記事・提出物を仕上げる | 初見の操作確認を行い、未対応・失敗・測定条件を正しく説明する |

写真読み込みはS1、画像出力はS3に関連する要望として残します。対応形式と提出時の範囲を手順1で決めます。期限が迫った場合も、シフト作成を恒久的な対象外にしたり、欠勤対応だけでプロジェクト全体を完成扱いにしたりしません。

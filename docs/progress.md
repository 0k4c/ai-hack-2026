# 進捗管理：最初はGitHub Issuesだけ

1件のIssueを1枚の作業カードとして使います。進捗の正本はGitHubです。**作成・状態更新・優先順位の整理はClaude Codeが担当し、Codexは実装結果を報告します。** 最終的な優先順位は人間が決めます。3人ともリポジトリに参加済みなので、IssueにAssignee（担当者）を設定できます。A・B・Cがそれぞれ誰かは最初の打ち合わせで決まるため、それまでは本文のA・B・Cを使います。

**2026-09-20：状態ラベル（`status:todo` / `status:doing` / `status:blocked`）を作成し、開いているIssueに付けました。** 日別マイルストーンは使っていません。日ごとの到達点は [ロードマップ](roadmap.md) を見てください。

- [タスク一覧](https://github.com/0k4c/ai-hack-2026/issues)
- [日ごとのまとまり](https://github.com/0k4c/ai-hack-2026/milestones)

## 状態は4つ

| 表示 | 意味 | やること |
| --- | --- | --- |
| `status:todo` | これから | 条件がそろったら着手 |
| `status:doing` | 作業中・レビュー待ち | 1人1件を目安に進める |
| `status:blocked` | 詰まっている | 困りごとと必要な助けを書く |
| Closed | 完了 | 完了条件を満たし、確認済み |

未完了のIssueには状態ラベルを1つだけ付けます。状態変更時は前のラベルを外します。閉じるときも状態ラベルを外します。レビュー中はdoingのまま、コメントで「レビュー待ち」と書きます。Claude Codeにこの操作を頼めます。

## 毎日の使い方

1. [ロードマップ](roadmap.md) で今日の到達点を確認する。
2. 担当するIssueを開き、先に終わっている必要がある作業と完了条件を読む。
3. Claude Codeへ着手を伝え、doingに更新する。30〜90分で見せられる小さな作業を1つ選ぶ。長ければチェック項目単位に分ける。
4. 実装はCodex、企画・管理文書はClaude Codeへ依頼する。画面・操作例・文書も成果として共有する。
5. 変更はPRにまとめ、別メンバーが確認する。修正してmainへマージされたら、Claude Codeが人間の確認結果と完了条件を照合して閉じる。

「テーマ未発表」「他の作業待ち」は本文に依存関係を残してtodo。着手後に解決できない問題が生じたらblockedにし、30分を目安に相談します。

## 初心者向けのCodexへの依頼

```text
このリポジトリのAGENTS.mdとdocs/team-playbook.mdに従ってください。
私は担当Bです。Issue番号は #ここに番号 です。
前提タスクが完了しているか確認し、まず次の30〜60分でやることを説明してください。
担当外のファイルを変える必要があれば、その理由と影響を説明してください。
作業ブランチで進め、変更を確認する操作手順を付けてDraft PRを作ってください。
実装結果をClaude Codeへ返せる形でまとめ、Issueの状態は変更しないでください。
```

Issueに書き込む状況報告のひな型：

```text
できたこと：
動作確認したこと／まだ確かめていないこと：
次にやること：
困っていること・手伝ってほしいこと：
PR・画像・結果：
```

## レビューはこの3点から

レビュー後の状態更新はClaude Codeへ依頼します。

- Issueに書いた操作をして、期待した結果になるか。
- 他の担当の機能が引き続き動くか。
- 変更内容をAIに説明させ、目的と関係ない変更や秘密情報が入っていないか。

コードが読めない箇所は、別のAIに差分レビューを依頼して理由を確認します。AIのレビューだけで済ませず、人が操作を試します。特に認証・支払い・個人情報を扱う機能は、十分確認できなければ今回の対象を小さくします。

## Claude Codeへ最初に頼むこと

```text
CLAUDE.mdとdocs/ai-roles.mdを読んでください。
企画・要件定義・ロードマップ・進捗管理を担当してください。
正式テーマが未発表なら未確定のままにし、まず3人の可動時間と運営条件を整理してください。
下の初期タスク案をもとに、既存Issueを確認して重複なくタスクを作成してください。
status:todo / status:doing / status:blockedのラベルと日別マイルストーンを用意し、
各Issueに人間の担当A/B/C、AIの担当、前提タスク、完了条件を書いてください。
実装はCodexへ引き継ぎ、完了条件を満たしたか確認して進捗を更新してください。
```

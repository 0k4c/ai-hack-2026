# 企画書（短いひな型）

状態：正式テーマ発表後。Claude Codeと3人で作成します。
企画書は「なぜ作るか」、[要件定義書](requirements.md) は「何ができれば完成か」を決める資料です。各欄1〜3行を目安にし、文書作りだけで時間を使い切らないようにします。

正式テーマは **業務を自律化するAIエージェント**（①判断する ②実行する ③記録する を人からAIへ移す）。
制作案の候補と比較は [制作案の候補](idea-candidates.md) にあります。まずそこで1案を選んでから、この文書を埋めてください。

## 企画の説明

- 仮タイトル：
- 一言で何をするものか：
- 誰の、どんな場面の困りごとか：
- 現状のやり方と困っている根拠（体験・観察・聞き取りなど）：
- 解決の流れと、AIを使う意味：
- 既存の方法と異なる1点：
- **AIに何を任せたか**（人が判断していた「入り口」のうち、どれをAIに選ばせたか）：

## デモで伝えること

- 使う前 → 使った後の変化：
- デモの入力と見せる結果：
- 効果をどう確かめるか：
- 現時点では仮説の部分・制約：

## 採用判断

- 3.5日で最小の形を作れる理由：
- 一番難しいことと、できない場合の縮小案：
- 今回作らないこと（要件定義書へ反映）：
- 3人が採用を決めた日時：

発表の骨子は「困りごと → デモ → 効果 → 工夫と限界」。4分＋質疑3分です。
機能・日程・タスク状態はそれぞれ要件定義書・ロードマップ・Issuesを参照し、ここに複製しません。

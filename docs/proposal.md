# 企画概要：ユーザーフレンドリーなAIシフト管理サービス

2026-09-21更新。[Issue #11](https://github.com/0k4c/ai-hack-2026/issues/11) のユーザー確認済みの主目的を反映しました。以下は概要のレビュー用です。詳細な勤務ルール、提出までの実装範囲、担当・日程は未確定です。

## 何を作るか

**従業員の勤務希望を集め、AIの支援でシフト案を作り、管理者が分かりやすい画面で確認・修正・確定できるサービス**を作ります。シフト作成から運用中の欠勤対応までをつなぎます。

想定する利用者は小規模店舗の店長・シフト管理者です。勤務希望の整理、必要人数との調整、修正のたびの確認にかかる手間を減らすことを目指します。負担の大きさや削減効果は仮説であり、利用者への検証はこれからです。

## 利用の流れ

1. **準備する**：従業員、作成する期間、時間帯ごとの必要人数、勤務条件を設定する。
2. **希望を取り込む**：勤務希望をAIが日付・時間・勤務可否に整理する。あいまいな内容は人が確認・修正する。
3. **シフト案を作る**：希望と条件をもとに対象期間のシフト表を作る。人数不足、重複、連勤・週労働時間などの問題を示す。
4. **調整して確定する**：管理者が表を見て修正し、条件を再確認して明示的に確定・保存する。
5. **欠勤に対応する**：確定後に欠勤が出たら、代打候補の選定・打診の支援につなぐ。

主な操作は画面上で進められ、利用者にコマンド操作やJSON編集を要求しません。AIの提案と確定済みの勤務を区別し、次に何をすればよいか分かる表示にします。AIが勝手に勤務を確定することはありません。

紙のシフト表の写真読み込みも当初の要望として維持します。画像としての表の出力は「可能なら対応」の要望です。対応する写真・入力形式や精度、提出時の対応範囲は別途決めます。

## 今どこまでできているか

現在は**欠勤対応の部品が先行した試作段階**です。希望文のAI解釈、勤務制約の判定、代打候補選定、返事に応じた再打診、判断・費用の記録、ローカルでの承認保存があります。打診は送信内容を記録するdryrunで、従業員への実送信はありません。

**シフト表全体の作成、必要人数などの設定画面、表の編集・確定画面はこれからです。** 現在の画面は主に欠勤対応の記録閲覧・承認用です。既存のCLIと画面の承認保存の不整合は [#34](https://github.com/0k4c/ai-hack-2026/issues/34) で扱います。欠勤対応だけの完成を、サービス全体の完成とは扱いません。

## 概要で確認したいこと

- 上記の「希望の取り込み → シフト案作成 → 調整・確定 → 欠勤対応」が想定するサービスの流れと合っているか。
- 最初に扱う対象期間（週・月など）、勤務時間の区切り方、必要人数の設定単位。
- 写真読み込みを含め、提出時に見せる範囲と、その後に作る範囲。

正式テーマは **業務を自律化するAIエージェント**です。AIには希望の整理や案の作成・調整の支援を任せ、条件の検証はコード、人の勤務確定は管理者の操作として設計します。デモでは「希望を入れ、問題を確認し、表を直して確定する」体験を中心に据え、実装済みの範囲と未実装の範囲を明示します。

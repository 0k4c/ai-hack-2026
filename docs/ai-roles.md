# Claude CodeとCodexの役割

2026-09-18のチーム方針。人間3人の分担は [チームの進め方](team-playbook.md) を参照。全員が初心者のため、AIへの依頼も小さな単位にします。

## 担当すること

| 項目 | 主担当 | 成果物 |
| --- | --- | --- |
| 誰の何を解決するか、アイデア比較 | Claude Code＋人間 | `docs/proposal.md` |
| 機能・作らないもの・完成条件 | Claude Code＋人間 | `docs/requirements.md` |
| 日程・タスク分解・担当・優先順位 | Claude Code | `docs/roadmap.md`、GitHub Issues |
| 進捗整理・詰まりの把握・計画調整案 | Claude Code | Issue更新、次の作業の提案 |
| 技術選定の実現性確認、環境構築 | Codex | 動作確認、設定、READMEの技術手順 |
| コーディング、テスト、修正、技術レビュー | Codex | コード、必要なテスト、PR、確認結果 |
| 発表の筋道・成果の整理 | Claude Code | 発表原稿・資料の構成案 |
| 企画の採用、範囲・支出の変更、レビュー・マージ、提出 | 人間3人 | 合意と実際の操作確認 |

Codexは企画・スケジュールを勝手に決め直さず、問題があれば影響と代案を返します。Claude Codeは実装に必要な仕様を整え、通常のコード変更はCodexへ渡します。ユーザーが別の役割を明示的に依頼した場合はその指示を優先します。今回の準備資料は、その依頼に基づきCodexで作成しています。

## 引き継ぐ流れ

1. 人間とClaude Codeで企画・要件を決める。
2. Claude Codeが、前提条件と完了条件のあるIssueを作る。
3. 担当メンバーがIssueのURLまたは内容をCodexへ渡す。
4. Codexが専用ブランチで実装・確認し、PRと結果を返す。
5. 別メンバーが差分と動作を確認する。必要ならCodexへ修正を依頼する。
6. レビュー後にPRをマージし、結果をClaude Codeへ渡す。
7. Claude Codeが完了条件を照合し、Issueの状態と次の作業を更新する。

**両AIを自動で連動させる設定はしていません。** 人間がIssue・PRのURLを渡す運用です。各自のツールから対象リポジトリを読み書きできることを確認してください。

## Claude Code → Codex

```text
担当Issue／担当メンバー：
目的（利用者ができるようになること）：
参照する要件ID：
先に完了すべきタスク：
変更してよい範囲・他の担当との境界：
入力例と期待する出力：
完了条件：
確認する操作・テスト：
今回やらないこと：

AGENTS.mdに従い、専用の作業ブランチで実装してください。
不明な仕様は推測で拡張せず、確認すべき点を示してください。
結果と確認手順を添えてDraft PRを作成し、Issueは完了にしないでください。
```

## Codex → Claude Code・人間

```text
担当Issue／PR：
実装したこと・主な変更ファイル：
完了条件ごとの結果：
実行した確認と結果（未実行なら理由）：
人間が操作して確かめる手順：
未解決点・制約・必要な設定：
他の担当や日程への影響：
レビュー・マージの状況：
```

## ファイルと進捗の管理

- Claude Code：企画・要件・進め方・ロードマップ・キックオフ情報・進捗ガイドとIssues。
- Codex：アプリコード、テスト、依存関係・開発環境、READMEの起動・技術手順。
- 共通ルールや役割の変更：人間の方針を確認して更新。
- 進捗の正本：GitHub Issues。文書に別の完了率を作らない。
- 1タスク1ブランチ。別AIセッションでは別worktreeまたはcloneを使い、相手の未コミット変更を触らない。
- Issue本文だけでなく、共有済みの要件とAGENTS.mdを読む。チャットにしかない重要な決定はClaude Codeが共有文書へ残す。

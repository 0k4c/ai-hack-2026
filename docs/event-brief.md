## テーマ（確定）

> **業務を自律化するAIエージェント**

資料では、テーマが4つの部品に分解されています。

| 部品 | 資料の説明 |
| --- | --- |
| モデル | 判断する頭脳。ここが差し替え可能かで5日目の伸びしろが変わる |
| ツール | 外部API・DB・社内システム。エージェントが「実行する」手足 |
| ループ | 結果を見て次を決める繰り返し。いつ止めるかまで設計する |
| 記録 | 誰が、何を、いくらで。運用・改善・監査の前提になる |

**「業務を自律化」＝ ①判断する ②実行する ③記録する を人からAIへ移すこと**、と定義されています。
このうちモデルと記録はOrcaRouterが引き受けるので、参加者はツールとループ（＝何を作るか）に集中してよい、という案内でした。

制作案の候補と比較は [制作案の候補](idea-candidates.md) にあります。

## 審査（確定）

5項目を各0〜10点、**合計50点満点**で採点します。

| # | 項目 | 資料の説明 |
| --- | --- | --- |
| 1 | セキュリティ | 情報漏洩や不正操作への対策が設計されているか |
| 2 | コストパフォーマンス | 品質と利用コストを適切に最適化できているか |
| 3 | 信頼性・堅牢性 | 想定外の入力やエラーでも安定して処理・復旧できるか |
| 4 | 自律性 | 状況を判断し、必要なツールを選んで遂行できるか |
| 5 | アイデア・独創性 | エージェントの特性を活かした新しい業務体験・課題解決 |

資料に明記されていた注意点です。制作案を選ぶときの判断材料にしてください。

- ①〜④は**設計で埋める**項目、⑤は**発想で埋める**項目。
- ⑤は「**既存の作業をどれだけ置き換えたか」ではなく「AIに何を任せたか**」を見る。
- ④の自律性は「決め打ちではなく、自分で選ぶ設計になっているか」。
- **自律性（④）が上がるほど、セキュリティ（①）と堅牢性（③）の要求は跳ね上がる。**人が押していたボタンをAIが押す以上、事故ったときの影響が大きいため。①②③④は連動していると説明されています。

## 使えるもの：OrcaRouter

スポンサーのOrcaRouterが、テーマのうち「モデル」と「記録」を担当する前提で案内されました。

- **1つのAPIキーで約200モデル**（資料p.5では9/17時点198モデル。利用可能なモデルは変動）
- **OpenAI SDK互換**。`base_url` と `api_key` の2行を差し替えるだけで動く。curlでもClaude Codeでも可
- マークアップ0%、無料枠あり。**Union Alpha**（無料・262Kコンテキスト・tool calling対応）
- クレジット **1人3,000円分**。受け取り：https://www.orcarouter.ai/redeem/ コード `AI-HACK-LOVES-ORCAROUTER`
- ドキュメント：docs.orcarouter.ai

ここにある機能・価格・無料モデルは配布時点のスポンサー説明です。実装時は [公式ドキュメント](https://docs.orcarouter.ai/introduction) と利用アカウントで設定・対応モデルを確認します。資料p.10では氏名・住所・社名は既定の検出対象外と明記されています。アプリの権限管理や業務操作の記録は別途必要です。

審査5項目に直接効く機能として、資料で紹介されていたものです。

| 審査項目 | 使える機能 |
| --- | --- |
| セキュリティ | Guardrails、PII Shield、Agent Firewall（inbound / response / MCP / egress）、権限を絞ったキー、Zero Retention |
| コスパ | `orcarouter/auto`（自動選択）、`orcarouter/free`（$0）、キャッシュ考慮、Request Logsで実費が見える |
| 信頼性 | Fallback、429とRetry-Afterの処理、モデル昇格、ストリーミング。OpenAI SDKなら `max_retries=2` |
| 自律性 | ツール呼び出し、MCP連携、モデル選択をコードに書かず任せる、セッション制御、**OrcaReplay**（実行の記録・再生・比較） |

**Named Router**：使ってよいモデルを絞り、`Mundane / Hard / Default` の戦略とFallbackを設定して、`orcarouter/<名前>` で呼べる仕組み。
「簡単な処理は安いモデル、難所だけ強いモデルへ昇格」を**コードを直さずに**実現でき、そのまま自律性とコスパの説明資料になります。

使い始めの順番として案内されていたのは、①まず `auto` で動かして記録を見る ②候補を絞る ③**Fallbackを必ず1つ設定する**、の3段階です。

### publicにする場合の注意

現在このリポジトリはPrivateで、[共通開発ルール](../AGENTS.md) もPrivate前提で書かれています。publicに切り替えるなら、**切り替える前に**次を確認してください。公開は取り消せません。

- `.env` や実際のAPIキー、トークンがコミット履歴に入っていないか（**現在のファイルだけでなく履歴全体**）
- 実在する個人情報を含むサンプルデータがないか
- 誰がいつ公開するかを3人で合意したか（[共通開発ルール](../AGENTS.md) は無断での公開化を禁止しています）

履歴に秘密情報が入っていた場合、publicにせずGoogleDriveでソースを提出する選択肢があります。こちらのほうが安全です。
